# 질문 개념 분류 평가

학습자의 질문을 개념에 맞게 분류하는 프롬프트를 여러 버전으로 시험한 결과입니다. 분류가 틀리면 꺼내 보기, 과거 질문 요약 같은 기능이 엉뚱한 개념에 연결되므로, 프롬프트를 바꾸기 전에 이 결과로 정확도를 확인합니다.

질문 개념 분류는 학습자의 질문이 어느 개념(단원 본문의 소제목 하나)에 대한 질문인지 AI가 고르는 단계입니다. 서비스에서는 `lib/llm/tagging.ts`의 `classifyQuestion`이 이 일을 합니다.

## 결과표 읽는 법

### 판정

질문마다 AI가 고른 개념을 정답(기대값)과 비교해서 넷 중 하나로 판정합니다.

| 판정 | 뜻 | 보는 법 |
| --- | --- | --- |
| 일치 | AI가 고른 개념이 정답과 같습니다. 정답이 "해당 개념 없음"이고 AI도 고르지 않은 경우도 일치입니다 | 높을수록 좋습니다 |
| 부분 일치 | 정답과 겹치는 개념이 있지만, 고른 개념 묶음이 정답과 다릅니다. 대부분 정답 개념에 다른 개념을 하나 더 고른 경우입니다 | "개념 하나만" 결정 이후에는 실패로 봅니다 |
| 불일치 | 정답 개념을 하나도 고르지 않았습니다 | 질문별 결과에서 어떤 개념을 골랐는지 확인하세요 |
| 오류 | 10초 안에 응답이 없거나 응답 형식이 깨졌습니다 | 서비스에서는 과거 요약 없이 답변하게 됩니다 |

### 숫자

| 항목 | 뜻 |
| --- | --- |
| 평균 시간, 최대 시간 | 분류 호출 하나에 걸린 시간입니다. 분류가 끝나야 답변을 시작하므로, 학습자가 첫 글자를 보기까지의 시간에 그대로 더해집니다 |
| 평균 입력 토큰 | 프롬프트, 개념 목록, 질문을 합친 길이입니다. 개념 목록이 길어지면 늘어납니다 |
| 질문 1,000건 비용 | 측정한 토큰에 Haiku 5.5 가격(100만 토큰당 입력 $0.10, 출력 $0.50)을 곱해서 1,000건으로 환산한 값입니다. 배치 할인과 프롬프트 캐시는 반영하지 않았습니다 |

### 질문 패턴

질문 세트는 학습자가 실제로 물을 만한 질문을 패턴별로 나눠 만들었습니다. 결과표의 "메모" 칸 앞부분이 패턴입니다. 특정 패턴에서만 틀린다면 그 유형의 질문에 프롬프트가 약하다는 뜻입니다.

| 패턴 | 설명 | 예시 |
| --- | --- | --- |
| P1 용어 직접 | 개념 이름이나 용어로 묻습니다 | LAG랑 LEAD는 뭐가 달라요? |
| P2 상황 설명 | 개념 이름 없이 하고 싶은 일을 말합니다 | 바로 앞 사람의 급여를 옆에 같이 보여 주고 싶어요 |
| P3 증상 | 실행 결과나 오류를 말합니다 | LAST_VALUE를 썼는데 자기 값이 나와요 |
| P5 개념 여러 개 | 개념 두 개에 걸쳐 묻습니다 | ROLLUP 결과를 GROUPING SETS로 똑같이 만들 수 있어요? |
| P6 목록 밖 | 개념 목록에 없는 내용을 묻습니다. 정답은 "해당 개념 없음"입니다 | UNION이랑 UNION ALL은 뭐가 달라요? |
| P7 맥락 의존 | 앞 대화 없이는 알 수 없는 질문입니다. 정답은 "해당 개념 없음"입니다 | 이거 왜 이렇게 돼요? |
| P8 구어 | 줄임말, 한글 표기, 오타가 섞인 질문입니다 | 덴스랭크 랭크 차이 ㅠ |
