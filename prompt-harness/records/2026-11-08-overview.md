# AI 프롬프트 검증 작업 정리 (2026-11-08 기준)

이 문서는 작업 내용을 처음 보는 사람이 전체 상황을 파악할 수 있도록 정리한 문서입니다. 트랙별 상세 수치와 실패 사례는 같은 폴더의 트랙별 문서에 있습니다.

## 1. 무엇을 하는 작업인가

서비스는 AI 기능 4개에 각각 프롬프트(AI에게 주는 지시문)를 씁니다. 지금 프롬프트는 짧은 초안이라서, 답이 지나치게 길거나 엉뚱한 요청을 따르는 등의 문제가 있는지 아무도 측정해 본 적이 없었습니다.

이 작업에서는 프롬프트마다 다음 순서로 더 나은 문장을 찾습니다.

1. 서비스와 같은 설정으로 AI를 부르는 시험 도구(하네스)를 만듭니다.
2. 같은 입력 세트로 지금 프롬프트(baseline)와 고친 프롬프트(변형)를 여러 번 돌립니다.
3. 품질, 응답 시간, 비용을 비교해서 서비스에 넣을 버전을 추천합니다.

품질은 세 가지 방법으로 확인합니다.

- **자동 검사:** 글자 수나 형식처럼 코드로 판정할 수 있는 항목은 코드로 판정합니다.
- **AI 판정:** 내용이 맞는지처럼 코드로 판정할 수 없는 항목은 상위 모델(Opus 5.5)에게 채점 기준을 주고 판정하게 합니다.
- **사람 검수:** AI 판정도 틀릴 수 있으므로, 일부 결과를 PO가 직접 확인하도록 목록을 따로 뽑아 둡니다.

## 3. 진행 중에 생긴 일

1. 공통 도구를 만든 뒤, 트랙 4개를 AI 에이전트 4개에 나눠 동시에 진행했습니다.
2. 실행 도중 API 사용 한도에 걸려 모든 호출이 막혔습니다. 한도는 2026-12-01에 풀립니다.
3. 사용자 지시로 API 키 대신 구독 계정(Claude Code CLI)으로 바꿔 실행했습니다.
4. 구독 방식은 서비스와 조건이 완전히 같지 않았습니다. 같은 입력을 두 방식으로 돌려 비교(보정)한 결과는 다음과 같습니다.
   - 일반 텍스트 답(트랙 A)은 두 방식에서 같게 나왔습니다.
   - JSON 형식 답(트랙 B, C, D)은 CLI에서 오류가 더 많이 나오는 경우가 있었습니다. 그래서 구독 방식 결과는 보정에서 API와 일치한 지표만 근거로 씁니다.
   - 응답 시간과 비용은 두 방식 사이에 비교할 수 없어서, 구독 방식에서 잰 값은 참고값으로만 씁니다.
5. 구독 사용량도 한도에 가까워져 모든 실행을 멈췄습니다. 그 뒤 서비스에 쓸 수 있는 트랙은 마무리하고, 아직 부족한 트랙은 개선을 이어 가기로 했습니다.

### B. 요약: 개선 중

- 지금 프롬프트는 요약에 실제 규칙을 적지 않고 주제 이름만 나열하는 문제가 있습니다. 예를 들어 "COUNT(*)는 NULL 행도 센다"라고 적어야 할 자리에 "GROUP BY 규칙을 설명했다"라고 적습니다. 이런 요약은 다음 답변이나 퀴즈 생성에 쓸모가 적습니다.
- 개선안 `v2-slots`는 전 항목 통과율을 77.2%에서 82.3%로 올렸습니다. 하지만 자세히 보면 이 차이는 모두 keywords 개수 규칙(1~5개)에서 나왔고, 나머지 기준에서는 지금 프롬프트가 약 7%p 더 좋았습니다. v2는 질문에 없는 학습자 의도를 추측해서 적는 문제도 생겼습니다. 이런 추측은 퀴즈 생성에 잘못된 정보를 줍니다.
- 이어서 두 버전을 3회씩 시험했습니다(구독 방식, 79쌍). 지금 프롬프트에 keywords 규칙만 더한 `r1-base-kw`는 keywords 개수는 고쳤지만, 주제 이름만 나열하는 문제가 그대로였습니다(전 항목 통과 86.9%). v2-slots에 "질문에 없는 의도는 추측하지 않는다"는 규칙을 더한 `r1-v2-nofab`은 모든 기준에서 가장 좋았습니다(전 항목 통과 94.9%, 최소 92.4%, 원문 충실 98.7%).
- **추천: `r1-v2-nofab`.** 개발에 넘길 문장 전문은 `2026-11-08-summary.md` 3절에 있습니다. 모든 수치가 구독 방식 결과이고 후속 질문 시험은 하지 못했으므로, API로 확인하려면 판정 비용 약 $12가 듭니다.
- 남은 실패는 대부분 의미 없는 입력이나 주입 시도에서 keywords를 채우는 경우였습니다. 11/8에 PO가 "학습과 무관한 입력이면 keywords를 비운다"는 기준을 정했습니다.
- 이 규칙을 별도 문장으로 더한 `r2-nofab-kw0`은 keywords를 잘 비웠지만(12건 중 10건) 원문 충실이 떨어졌습니다. 규칙을 기존 keywords 문장 안에 합친 `r2b-nofab-kw0-folded`는 요약 품질을 유지했지만(빠른 세트 판정 통과 93.3%), keywords는 12건 중 6건만 비웠습니다. 두 버전 모두 정상 질문의 keywords를 잘못 비운 경우는 없었습니다.
- **최종 추천: `r2b-nofab-kw0-folded`.** 요약 문장의 품질이 답변과 퀴즈 생성에 모두 영향을 주기 때문입니다. 남은 keywords 누수는 서비스 코드에서 막거나 감수할 수 있습니다.

### C. 서술형 채점: 방식은 유력하지만 PO 결정이 필요함

- 지금 프롬프트는 핵심 요소가 하나 빠진 답을 맞다고 판정한 경우가 96건 중 3건 있었습니다. 다만 이 3건은 프롬프트보다 라벨 쪽 문제일 수 있습니다. 2건은 빠졌다는 핵심 요소를 문제가 아예 묻지 않고, 1건은 빠진 요소가 다른 요소와 내용이 겹칩니다. 그래서 프롬프트를 이 라벨에 맞춰 고치지 않고 PO 검수 목록에 올렸습니다.
- `checklist` 방식이 가장 유력합니다. 이 방식에서는 AI가 핵심 요소마다 짚었는지만 판정하고, 맞음과 틀림은 코드가 계산합니다. 라벨과 96건 중 95~96건이 일치했고, 3번 돌려도 판정이 바뀌지 않았습니다.
- 서비스에 넣기 전에 PO가 정할 것이 있습니다.
  - 채점 기준을 A(핵심 요소를 모두 짚어야 맞음)로 할지, B(절반 이상 짚으면 맞음)로 할지 정해야 합니다.
  - 정답 라벨 초안 96건을 검수해야 합니다.
  - checklist를 쓰려면 응답 형식이 바뀌므로, ADR 0010을 다시 검토해야 합니다.
- 보정 결과, 같은 24건에서 구독 방식과 API의 판정이 모두 같았습니다. 다만 문제 하나로만 확인했습니다.
- 기준 A와 기준 B를 각각 프롬프트에 직접 적은 버전(crit-a, crit-b)과도 비교했습니다(구독 방식, 3회).

| 버전 | 기준 A 라벨 일치 | 기준 B 라벨 일치 | 3회 사이 판정 바뀜 |
| --- | --- | --- | --- |
| crit-a | 93~94/96 | - | P04 1건 |
| crit-b | - | 93~95/96 | 3건(모두 "절반" 경계의 답) |
| checklist | 96/96 | 95/96 | 0건 |

- checklist가 기준 A에서 앞선 것은 모두 라벨 검수 대상 3건 덕분입니다. 기준 B에서 앞선 것은 "절반 짚음" 경계에 있는 답에서도 판정이 흔들리지 않기 때문입니다.
- 개발에 넘길 checklist 후보(프롬프트, 응답 형식, 코드에서 A·B를 판정하는 규칙)는 `2026-11-08-grading.md` 10절에 있습니다. 서비스에 넣기 전에 API 조건으로 한 번 확인해야 합니다.
- PO가 볼 라벨은 12건으로 늘었습니다. 핵심 질문은 "문제가 묻지도 않은 핵심 요소가 빠졌을 때 그 답을 틀렸다고 볼지"입니다.

### D. 퀴즈 생성: 개선 중

- 지금 프롬프트의 첫 문장이 "정보처리기사"로 되어 있습니다. 이 서비스는 SQLD 학습 서비스이므로 "SQLD"로 고쳐야 하고, 이 수정은 바로 반영하면 됩니다.
- 가장 큰 문제는 빈칸 문제입니다. 빈칸 문제 30건 중 10건은 문제가 정답 용어의 정의를 알려 줘서 지나치게 쉬웠고, 12건은 힌트가 정답을 거의 알려 줬습니다.
- 이 문제를 고친 `v2-blank`를 시험했습니다(구독 방식, 빈칸 문제 30건). 지나치게 쉬운 문제는 66.7%에서 96.7%로, 힌트 안전은 70.0%에서 96.7%로 좋아졌습니다. 하지만 정답 정확도가 86.7%에서 70.0%로 떨어졌습니다. 해설의 계산 결과와 정답 칸의 값이 어긋나는 오류가 생겼기 때문입니다.
- 이 오류를 막는 규칙을 더한 `v3-blank`는 빈칸 정답 정확도를 93.3%로 회복했습니다. 하지만 그 규칙이 모든 형식에 적용되어 객관식과 서술형의 정답 오류가 늘었습니다.
- 그 규칙을 빈칸 문제 전용 지시로 옮긴 `v4-blank`가 가장 좋았습니다(빠른 세트, 빈칸 10건 × 2회). 지금 문장과 비교하면 빈칸 문제 전 항목 통과가 30%에서 95%로, 힌트 안전이 65%에서 100%로, 정답 정확도가 80%에서 95%로 올랐습니다.
- **추천: `v4-blank`.** 개발에 넘길 문장 전문은 `2026-11-08-quiz-generation.md` 6절에 있습니다. 근거가 모두 구독 방식 결과이므로, 서비스에 넣기 전에 API 조건으로 한 번 확인하는 것을 권합니다(약 $22).
