### 2. d36 · baseline · 3회차 · API 생성 + CLI 판정

- 절: s2-12-4 비율 함수
- 형식: 객관식, 맥락: 요약 여러 개(퀴즈 탭)
- 자동 검사: 통과

````text
[문제]
다음은 급여(SAL) 오름차순으로 정렬한 5명의 데이터다.

```
ENAME  SAL
A      100
B      200
C      200
D      300
E      400
```

이 데이터에 다음 쿼리를 실행했을 때, 이름이 C인 행의 PR, CD, NT 값을 순서대로 올바르게 나열한 것은? (NTILE의 ORDER BY는 SAL, ENAME 기준으로 순서가 고정되어 있다.)

```sql
SELECT ENAME, SAL,
       PERCENT_RANK() OVER (ORDER BY SAL) AS PR,
       CUME_DIST()    OVER (ORDER BY SAL) AS CD,
       NTILE(2)       OVER (ORDER BY SAL, ENAME) AS NT
FROM T;
```

[보기]
1. 0.25, 0.4, 1
2. 0.25, 0.6, 1  ← 정답으로 표시됨
3. 0.5, 0.6, 2
4. 0.25, 0.6, 2

[힌트]
PERCENT_RANK는 RANK를 이용해 (RANK-1)÷(행 수-1)로 계산하고, CUME_DIST는 동점 묶음의 마지막 행까지 세며, NTILE은 동점과 상관없이 행 수만으로 나눈다.

[해설]
C의 SAL 200은 B와 동점이라 RANK가 2이다. PR은 (2-1)÷(5-1)=0.25이다. CD는 현재 값 200 이하인 행이 A, B, C 3개이므로 3÷5=0.6이다. NTILE(2)는 5행을 2그룹으로 나누면 나머지 1행이 앞 그룹에 가서 크기가 3, 2가 된다. 정렬 순서가 A, B, C, D, E이므로 C는 3번째 행이라 1그룹이다. 따라서 0.25, 0.6, 1이 정답이다.
````

| 정답 하나·맞음 | 통과 | C의 RANK는 2이므로 PR=(2-1)/(5-1)=0.25, CD=3/5=0.6이고, NTILE(2)는 3행·2행으로 나뉘어 세 번째 행인 C가 1그룹이므로 정답 보기 2만 맞고 나머지 보기는 모두 틀리다. |

### 3. d22 · baseline · 3회차 · API 생성 + CLI 판정

- 절: s2-09-4 NOT IN과 NULL 함정
- 형식: 서술형, 맥락: 질문과 답 원문(관련 문제)
- 자동 검사: 통과

````text
[문제]
부서 테이블 DEPT에는 부서 번호 10, 20, 30이 있고, 사원 테이블 EMP의 DEPTNO 컬럼에는 10, 20, NULL 값만 들어 있다(30번 부서에는 사원이 없다). 사원이 없는 부서를 찾으려고 아래 SQL을 실행했더니 30번 부서가 나오지 않고 0행이 반환되었다.

```sql
SELECT D.DEPTNO, D.DNAME
FROM DEPT D
WHERE D.DEPTNO NOT IN (SELECT E.DEPTNO FROM EMP E);
```

(1) 0행이 되는 이유를 30번 부서를 예로 들어 NOT IN이 변환되는 조건식과 논리 판정 과정으로 설명하시오.
(2) 30번 부서가 나오도록 고치는 방법을 두 가지 쓰시오.

[모범 답]
(1) 서브쿼리 결과가 {10, 20, NULL}이므로 30 NOT IN (10, 20, NULL)은 30<>10 AND 30<>20 AND 30<>NULL로 바뀐다. 앞의 둘은 참이지만 NULL과의 비교는 UNKNOWN이고, 참 AND 참 AND UNKNOWN은 UNKNOWN이다. WHERE는 참인 행만 남기므로 30번 부서도 제외되어 0행이 된다. (2) 첫째, 서브쿼리에 WHERE E.DEPTNO IS NOT NULL을 추가해 NULL을 제거한다. 둘째, NOT EXISTS (SELECT 1 FROM EMP E WHERE E.DEPTNO = D.DEPTNO)로 바꾼다. 두 방법 모두 30 기획 1행이 나온다.

[채점 핵심 요소]
- 서브쿼리 결과에 NULL이 포함되어 있음(조미정의 부서가 NULL)
- NOT IN은 목록의 각 값과 <> 비교를 AND로 연결한 것과 같음
- NULL과의 <> 비교는 UNKNOWN이며 AND에 UNKNOWN이 섞이면 참이 될 수 없음
- WHERE는 참인 행만 남기므로 30번도 제외되어 0행
- 해결 방법 1: 서브쿼리에서 IS NOT NULL로 NULL 제거
- 해결 방법 2: NOT EXISTS 사용(NULL의 영향을 받지 않음)

[힌트]
NOT IN은 목록의 모든 값과 다르다는 뜻이므로 AND로 이어진 비교로 바뀝니다. NULL과 비교하면 참, 거짓 중 무엇도 아닌 세 번째 판정값이 나옵니다. WHERE는 어떤 행만 남기는지 떠올려 보세요.

[해설]
서브쿼리 결과는 {10, 20, NULL}이고, 30 NOT IN (10, 20, NULL)은 30<>10 AND 30<>20 AND 30<>NULL로 바뀝니다. 앞의 두 비교는 참이지만 NULL과의 비교는 UNKNOWN이므로, 참 AND 참 AND UNKNOWN은 UNKNOWN이 됩니다. WHERE는 참인 행만 남기므로 30번 부서도 걸러져 0행이 됩니다. 10, 20번은 목록에 있어 원래 거짓입니다. 해결책은 서브쿼리에서 NULL을 제거하거나(WHERE E.DEPTNO IS NOT NULL), NULL의 영향을 받지 않는 NOT EXISTS를 쓰는 것입니다. 둘 다 30 기획 1행이 나옵니다.
````

| 항목 | AI 판정 | 근거 |
|---|---|---|
| 출제 범위 | 통과 | NOT IN 서브쿼리 결과에 NULL이 섞이면 0행이 되는 함정과 그 해결법을 묻고 있어 target_section 내용과 정확히 맞는다. |
| 정답 하나·맞음 | 통과 | NOT IN을 AND 조건으로 바꿔 UNKNOWN이 되는 과정과 IS NOT NULL·NOT EXISTS 두 해결법이 모두 맞고, 무엇을 써야 하는지도 질문에 분명히 나와 있다. |

### 5. d20 · baseline · 3회차 · API 생성 + CLI 판정

- 절: s2-09-3 연관 서브쿼리와 EXISTS
- 형식: 객관식, 맥락: 질문과 답 원문(관련 문제)

````text
[문제]
다음 두 테이블이 있다.

```
DEPT: (10, 개발), (20, 영업), (30, 기획)
EMP의 DEPTNO 값: 10, 10, 20, 20, 10
```

아래 쿼리를 실행했을 때의 결과로 옳은 것은?

```sql
SELECT D.DNAME
FROM DEPT D
WHERE EXISTS (SELECT 1
              FROM EMP E
              WHERE E.DEPTNO = D.DEPTNO);
```

[보기]
1. 개발, 영업  ← 정답으로 표시됨
2. 기획
3. 개발, 영업, 기획
4. 서브쿼리의 SELECT 1 때문에 오류가 난다

[힌트]
````

````text
SELECT DEPTNO, ENAME, AVG(SAL)
FROM EMP
GROUP BY DEPTNO;

-- SQL 2
SELECT DEPTNO AS D, AVG(SAL)
FROM EMP
GROUP BY D;

각 SQL에서 오류가 발생하는 이유를 GROUP BY의 규칙과 SQL 처리 순서를 근거로 설명하고, 두 SQL을 오류 없이 고치는 방법을 쓰시오.

[모범 답]
SQL 1은 GROUP BY DEPTNO로 부서마다 한 행만 남는데, ENAME은 GROUP BY에 쓰지 않은 컬럼이라 한 부서의 여러 사원 이름 중 하나만 한 행에 보여 줄 수 없다. SELECT에는 GROUP BY 컬럼, 집계 함수, 상수만 쓸 수 있으므로 오류가 난다. [채점 핵심 요소]

- SELECT에는 GROUP BY에 쓴 컬럼, 집계 함수, 상수만 쓸 수 있다
````

````text
  ON D.DEPTNO = E.DEPTNO

[모범 답]
````

### 17. d13 · baseline · 2회차 · API 생성 + CLI 판정

- 절: s2-07-6 NATURAL JOIN과 USING 절
- 형식: 서술형, 맥락: 질문과 답 원문(관련 문제)
- 자동 검사: 통과

````text
[문제]
DEPT(컬럼 3개: DEPTNO, DNAME, LOC)와 EMP(컬럼 8개: DEPTNO를 포함)를 DEPTNO로 조인한다. 아래 두 쿼리는 각각 사원 번호 1003인 사원 한 행을 조회한다.

```sql
-- (1)
SELECT *
FROM DEPT D JOIN EMP E
  USING (DEPTNO)
WHERE EMPNO = 1003;

-- (2)
SELECT *
FROM DEPT D JOIN EMP E
  ON D.DEPTNO = E.DEPTNO
WHERE EMPNO = 1003;
```

(1)과 (2)의 결과 컬럼 수를 각각 쓰고, 차이가 생기는 이유를 설명하라. 또 (1)에서 `SELECT E.DEPTNO`처럼 공통 컬럼에 테이블 접두사를 붙이면 오류가 나는 이유도 함께 서술하라.

[모범 답]
(1) USING은 10개, (2) ON은 11개이다. USING은 공통 컬럼 DEPTNO를 하나로 합쳐 맨 앞에 한 번만 보여 주므로 3 + 8 − 1 = 10개가 된다. ON은 두 테이블의 DEPTNO를 각각 별개 컬럼으로 유지하므로 3 + 8 = 11개이고 DEPTNO가 두 번 나온다. USING의 공통 컬럼은 하나로 합쳐진 컬럼이라 어느 테이블 소속인지 구분할 수 없으므로 E.DEPTNO처럼 접두사를 붙이면 오류가 나고, DEPTNO라고만 써야 한다.

[채점 핵심 요소]
- USING 결과는 10개 컬럼, ON 결과는 11개 컬럼
- USING은 공통 컬럼을 하나로 합쳐 한 번만 출력(3+8−1)
- ON은 양쪽 DEPTNO를 각각 유지하여 DEPTNO가 두 번 나옴(3+8)
- 공통 컬럼이 하나로 합쳐져 소속 테이블 구분이 불가능하므로 접두사를 붙이면 오류
- 공통 컬럼은 접두사 없이 DEPTNO로만 써야 함

[힌트]
USING은 이름이 같은 조인 컬럼을 결과에서 몇 개의 컬럼으로 다루는지 생각해 보세요. 3 + 8에서 무엇을 빼야 할까요?

[해설]
USING(그리고 NATURAL JOIN)은 조인에 쓴 공통 컬럼 DEPTNO를 두 테이블의 컬럼이 아닌 하나로 합쳐진 컬럼으로 처리해 결과에 한 번만 보여 준다. 그래서 (1)은 3 + 8 − 1 = 10개 컬럼이다. ON은 두 테이블의 DEPTNO를 각각 별개 컬럼으로 두므로 (2)는 3 + 8 = 11개 컬럼이고 DEPTNO가 두 번 나온다. USING에서는 공통 컬럼이 어느 한 테이블의 것이 아니므로 E.DEPTNO처럼 접두사를 붙여 어느 테이블 것인지 지정할 수 없고 오류가 난다(Oracle ORA-25154 등). 접두사 없이 DEPTNO라고만 써야 한다.
````

````text
아래 테이블 T와 쿼리가 있다. 쿼리 결과의 RES 컬럼은 각 행마다 자기 자신의 NM 값과 같게 나온다. 빈칸에 들어갈 함수 이름을 쓰시오.

| NM | SCORE |
| -- | -- |
| A | 10 |
| B | 20 |
| C | 30 |
| D | 40 |

```sql
SELECT NM, SCORE,
       ____(NM) OVER (ORDER BY SCORE) AS RES
FROM T
ORDER BY SCORE;
```

[정답으로 인정하는 답(accepted)]
LAST_VALUE / last_value

[힌트]
ORDER BY만 쓰면 계산 범위가 어디서 어디까지인지 생각해 보세요. 그 범위의 끝은 각 행마다 어디일까요?

[해설]
LAST_VALUE에 ORDER BY만 쓰면 기본 프레임이 처음부터 현재 행까지입니다. 그래서 프레임의 마지막 값은 항상 현재 행의 값입니다. 점수 순서로 보면 A행은 A, B행은 B, C행은 C, D행은 D가 나옵니다. 따라서 결과가 이런 형태가 되는 함수는 LAST_VALUE입니다. 파티션 전체의 마지막 값을 얻으려면 프레임을 UNBOUNDED FOLLOWING까지 넓혀야 합니다.
````
