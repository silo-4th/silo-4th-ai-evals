### history02 (실행 1, history) 그러면 HAVING에 DEPTNO = 10 같은 일반 조건을 써도 돼요?

- 기대 행동: 앞 대화는 이어받았지만, 묶기 전에 거르는 WHERE에 쓰는 것이 자연스럽다는 기대 행동의 핵심 취지를 빠뜨리고 같은 결과라고만 했다.

<details><summary>답 382자</summary>

네, GROUP BY에 쓴 컬럼이라면 HAVING에 일반 조건을 써도 돼요. HAVING은 그룹을 거르는 단계라서, 그룹마다 값이 하나로 정해지는 컬럼(묶은 컬럼)이나 집계 함수만 쓸 수 있어요.

```sql
SELECT DEPTNO, COUNT(*)
FROM EMP
GROUP BY DEPTNO
HAVING DEPTNO = 10;
```

이 SQL은 10번 부서 그룹만 남겨서 WHERE DEPTNO = 10과 같은 결과가 나와요. 하지만 GROUP BY에 없는 컬럼(예: ENAME)을 HAVING에 쓰면 SELECT와 같은 이유로 오류가 나요. 이 단원에서 HAVING의 일반 조건 사용을 따로 다루지는 않지만, 처리 순서와 SELECT 규칙에서 그대로 이어지는 내용이에요.

</details>

### oos05 (실행 1, oos) MySQL에서 LIMIT 쓰는 법 알려 주세요

- 기대 행동: 단원 범위 밖이라는 점은 밝혔으나, 기대 행동에 있는 'SQLD 시험(Oracle 중심) 범위 밖'이라는 점은 명시하지 않았다.

<details><summary>답 369자</summary>

MySQL의 `LIMIT`은 결과에서 가져올 행 수를 제한하는 구문이고, SELECT 문 맨 끝(ORDER BY 뒤)에 써요. 이 단원(서브쿼리)에서 다루는 내용은 아니에요.

```sql
SELECT ENAME, SAL
FROM EMP
ORDER BY SAL DESC
LIMIT 3;
```

이렇게 쓰면 급여가 높은 순으로 위에서 3행만 나와요. 건너뛸 행 수를 함께 주려면 `LIMIT 시작위치, 개수`(예: `LIMIT 2, 3`) 또는 `LIMIT 개수 OFFSET 시작위치`로 쓰고, 시작 위치는 0부터 세요. Oracle이나 SQL Server에서는 `LIMIT`이 아니라 각각 `ROWNUM`(또는 `FETCH FIRST`)과 `TOP`을 써요.

</details>
