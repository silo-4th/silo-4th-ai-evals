```sql
SELECT JOB, AVG(SAL)
FROM EMP
WHERE DEPTNO = 10
GROUP BY JOB
HAVING AVG(SAL) >= 4000;
```

<details><summary>답 1097자</summary>

WHERE와 HAVING의 차이는 "언제, 무엇을 거르느냐"예요. 처리 순서를 따라 단계별로 풀어 볼게요.

**1. 처리 순서**

SQL은 FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY 순서로 처리돼요. WHERE는 GROUP BY보다 앞이라 개별 행을 거르고, HAVING은 GROUP BY 뒤라 묶인 그룹을 걸러요.

**2. 집계 함수를 WHERE에 못 쓰는 이유**

WHERE를 처리하는 시점에는 아직 그룹이 만들어지기 전이라 SUM이나 AVG 값이 존재하지 않아요. 그래서 `WHERE AVG(SAL) >= 4000`처럼 쓰면 ORA-00934 오류가 나고, 집계 조건은 HAVING에 써야 해요.

**3. 두 조건을 함께 쓴 예제 따라가기**

"10번 부서에서, 직무별 평균 급여가 4000 이상인 직무"를 구하는 SQL이에요.

```sql
SELECT JOB, AVG(SAL) AS AVG_SAL
FROM EMP
WHERE DEPTNO = 10
GROUP BY JOB
HAVING AVG(SAL) >= 4000
ORDER BY JOB;
```

- **WHERE:** 10번 부서 6명만 남아요. 박영업은 MANAGER지만 20번 부서라서 여기서 빠져요.
- **GROUP BY:** 남은 6명을 직무로 묶어요. CEO는 김대표(9000), MANAGER는 이개발(6000), DEV는 최코드(4000), 정코드(4000), 강신입(3000), 서인턴(NULL)이에요.
- **HAVING:** DEV의 평균은 서인턴을 빼고 11000 ÷ 3 = 3666.7이라 4000보다 작아서 빠져요. CEO와 MANAGER만 남아요.

| JOB | AVG_SAL |
| -- | -- |
| CEO | 9000 |
| MANAGER | 6000 |

**4. GROUP BY 없이 HAVING만 쓰는 경우**

이때는 테이블 전체가 그룹 하나가 돼요. `HAVING MAX(SAL) > 5000`은 최고 급여가 9000이라 통과해서 한 행이 나오고, `HAVING COUNT(*) > 100`으로 바꾸면 그룹 하나가 통째로 빠져서 아무 행도 나오지 않아요.

참고: 3. WHERE와 HAVING

> [AI] WHERE는 그룹으로 묶기 전에 행을 거르고, HAVING은 묶은 뒤에 그룹을 걸러요. SQL 처리 순서가 FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY라서 이런 차이가 생겨요. WHERE를 처리하는 시점에는 아직 그룹이 없어서 SUM이나 AVG 같은 집계 값도 없어요. 그래서 집계 함수를 쓰는 조건은 HAVING에 써야 하고, WHERE에 쓰면 ORA-00934 오류가 나요.

```sql
SELECT JOB, AVG(SAL)
FROM EMP
WHERE DEPTNO = 10        -- 묶기 전: 10번 부서 행만
GROUP BY JOB
HAVING AVG(SAL) >= 4000; -- 묶은 뒤: 평균 4000 이상 그룹만
```

참고: 3. WHERE와 HAVING
