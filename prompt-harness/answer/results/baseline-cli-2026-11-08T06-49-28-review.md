| 기준 | 판정 | 근거 |
|---|---|---|
| 정확성 | 통과 | GROUP BY는 그룹당 한 행, 윈도우 함수는 원래 행 수를 유지한다는 설명과 20번 부서 합계 12500 등 값이 모두 맞다. |
| 질문에 답함 | 통과 | 행 수가 다른 이유를 바로 설명했고 표와 정리도 질문 범위 안에 있어 지나치게 길지 않다. |

<details><summary>답 718자</summary>

역할이 달라서 그래요. GROUP BY는 **행을 그룹으로 합치는** 도구이고, 윈도우 함수는 **행은 그대로 두고 옆에 계산값을 붙이는** 도구예요.

**GROUP BY**
- 그룹마다 결과를 한 행으로 줄여요.
- 20번 부서 3명을 `GROUP BY DEPTNO`로 묶으면 `20, 12500` 한 행만 남아요.
- 그래서 SELECT에는 그룹 기준 컬럼이나 집계 결과만 쓸 수 있고, 개별 사원의 이름이나 급여는 같이 볼 수 없어요.

**윈도우 함수**
- `SUM(SAL) OVER (PARTITION BY DEPTNO)`처럼 쓰면 계산은 그룹 단위로 하지만, 원래 행 수는 그대로예요.
- 단원 예제에서 20번 부서는 박영업, 한세일, 윤세일 3행이 모두 남고, 각 행에 같은 합계 12500이 붙었어요.
- 그래서 개별 사원의 급여와 부서 합계를 한 행에서 같이 볼 수 있어요.

| 구분 | GROUP BY | 윈도우 함수 |
| -- | -- | -- |
| 결과 행 수 | 그룹 수만큼 (20번 부서 → 1행) | 원래 행 수 그대로 (20번 부서 → 3행) |
| 개별 행의 컬럼 | 함께 보여 줄 수 없음 | 함께 보여 줄 수 있음 |
| 그룹을 나누는 방법 | GROUP BY | OVER 안의 PARTITION BY |

정리하면 "부서별 합계만 필요하다"면 GROUP BY, "각 사원 옆에 부서 합계나 순위를 붙이고 싶다"면 윈도우 함수를 쓰면 돼요.

</details>

<details><summary>답 708자</summary>

네, 비슷한 방식이에요. 둘 다 ORDER BY 값이 같은 행(동점)을 한 묶음으로 보고 같은 결과를 줘요. 다만 "같은 값"이 어떤 값인지가 달라요.

| -- | -- | -- |

### s049 (single, 단원 s2-09) 통과

**질문:** NOT IN 대신 NOT EXISTS를 쓰라는 이유가 뭐예요?




**AI 판정:**

| 기준 | 판정 | 근거 |
|---|---|---|
| 정확성 | 통과 | NOT IN의 AND 변환과 UNKNOWN 처리, NOT EXISTS의 동작, IS NOT NULL로 피하는 방법, IN의 OR 동작이 모두 단원 본문과 맞다. |
| 질문에 답함 | 통과 | 질문한 이유(NULL 함정)에 바로 답했다. 마지막 IN 언급은 짧은 보충이라 답이 눈에 띄게 길어지지 않았다. |
| 단원 근거 | 통과 | 조미정의 DEPTNO NULL, 30 기획, {10,20,NULL} 등 단원 데이터와 예제를 그대로 썼고 지어낸 값이 없다. |

**PO 확인:** [ ] 판정에 동의 [ ] 판정이 틀림 (메모: )

<details><summary>답 925자</summary>

이유는 **NULL 때문에 NOT IN은 결과가 틀어질 수 있지만, NOT EXISTS는 그렇지 않기 때문**이에요.

**NOT IN의 문제**

`NOT IN`은 "목록의 모든 값과 다르다"는 뜻이라 `AND`로 이어진 비교로 바뀌어요. 서브쿼리 결과가 {10, 20, NULL}이면 30번 부서는 이렇게 돼요.

`30 <> 10 AND 30 <> 20 AND 30 <> NULL`

앞의 둘은 참이지만 `30 <> NULL`은 UNKNOWN이라서 전체가 UNKNOWN이 되고, WHERE는 참인 행만 남기기 때문에 결과가 **0행**이 돼요. 이 단원 데이터에서는 조미정의 DEPTNO가 NULL이라서, "사원이 없는 부서"를 찾을 때 30 기획이 나와야 하는데 아무것도 안 나와요.

**NOT EXISTS는 왜 안전한가**

`NOT EXISTS`는 값을 비교해서 참/거짓을 따지는 게 아니라, 연관 서브쿼리에서 "짝이 되는 행이 있는가"만 봐요.

- 30번 기획의 서브쿼리 `WHERE E.DEPTNO = D.DEPTNO`는 맞는 행이 0개예요.
- NULL인 조미정은 어떤 부서와도 짝이 안 되니 그냥 무시돼요.
- 행이 없으니 NOT EXISTS가 참이 되어 30 기획이 정상으로 나와요.

**정리**

| 방식 | 서브쿼리에 NULL이 있을 때 |
| -- | -- |
| `NOT IN` | 0행 (함정) |
| `NOT EXISTS` | 정상 (30 기획 1행) |

NOT IN을 꼭 써야 한다면 서브쿼리에 `WHERE E.DEPTNO IS NOT NULL`을 붙여 NULL을 빼면 돼요. 하지만 NULL이 들어올 가능성을 매번 신경 써야 하니, 실수를 줄이려고 NOT EXISTS를 권하는 거예요.

참고로 `IN`은 `OR`로 이어지기 때문에 NULL이 섞여도 괜찮아요. NULL이 문제를 일으키는 건 NOT IN뿐이에요.

</details>

<details><summary>답 736자</summary>

**등가 조인(EQUI JOIN)**은 두 테이블의 컬럼 값이 `=`로 같은 행끼리 이어 붙이는 조인이에요. 보통 한 테이블의 기본키(PK)와 다른 테이블의 외래키(FK)를 연결해요.

단원 예제에서는 EMP.DEPTNO(외래키)와 DEPT.DEPTNO(기본키)를 연결했어요.

```sql
SELECT E.ENAME, E.DEPTNO, D.DNAME
FROM EMP E, DEPT D
WHERE E.DEPTNO = D.DEPTNO
ORDER BY E.EMPNO;
```

**Oracle 전통 문법 (+)**

```sql
SELECT E.ENAME, E.DEPTNO, D.DNAME
FROM EMP E, DEPT D
WHERE E.DEPTNO = D.DEPTNO(+)
ORDER BY E.EMPNO;
```

두 쿼리 모두 10행이 나오고, 조미정은 DEPTNO와 DNAME이 NULL인 채로 포함돼요.

| ENAME | DEPTNO | DNAME |
| -- | -- | -- |
| … | … | … |
| 조미정 | NULL | NULL |
| 서인턴 | 10 | 개발 |

1. 조미정은 EMP 쪽 행이니까 EMP가 모두 남는 쪽이어야 해요. LEFT JOIN에서는 EMP를 왼쪽에 쓰고, `(+)`에서는 NULL로 채워질 DEPT 쪽 컬럼에 `(+)`를 붙여요.

## OFFSET으로 건너뛰기

두 가지 표기가 있어요.

```sql
LIMIT 건너뛸_개수, 가져올_개수;
LIMIT 가져올_개수 OFFSET 건너뛸_개수;
```

앞의 3명을 건너뛰고 그다음 3명:

```sql
SELECT ENAME, SAL
FROM EMP
ORDER BY SAL DESC
LIMIT 3 OFFSET 3;
-- 같은 뜻: LIMIT 3, 3
```

콤마 표기는 **순서가 (건너뛸 개수, 가져올 개수)**라서 헷갈리기 쉬워요. `OFFSET`을 쓰는 표기가 읽기 편해요.

```sql
                       ORDER BY SAL DESC
```

## EXISTS란?

EXISTS는 서브쿼리 결과가 **한 행이라도 있으면 참**, **한 행도 없으면 거짓**이 되는 연산자예요. 행이 있는지만 보고 값은 보지 않기 때문에, 서브쿼리의 SELECT에는 `SELECT 1`이나 `SELECT 'X'`처럼 아무 값이나 써도 돼요. 주로 메인쿼리의 컬럼을 쓰는 연관 서브쿼리와 함께 써요.

```sql
SELECT D.DEPTNO, D.DNAME
FROM DEPT D
WHERE NOT EXISTS (SELECT 1
                  FROM EMP E
                  WHERE E.DEPTNO = D.DEPTNO)
ORDER BY D.DEPTNO;
```

| -- | -- |
| 30 | 기획 |

3. 30번 기획은 서브쿼리가 0행이라 NOT EXISTS가 참이 되어 남아요.

네, 만들 수 있어요. ROLLUP이 만드는 묶음 단계를 GROUPING SETS에 직접 나열하면 됩니다.

| 그룹 함수 | 같은 결과를 내는 GROUPING SETS |
| -- | -- |
| ROLLUP(A, B) | GROUPING SETS((A, B), A, ()) |

ROLLUP(A, B)는 오른쪽 컬럼부터 하나씩 빼면서 묶기 때문에 다음 세 단계가 만들어져요.

- (A, B): 상세 행
- (A): B를 뺀 A별 소계
- (): 총계

이 세 가지를 GROUPING SETS에 그대로 적으면 돼요.

```sql
SELECT DEPTNO, YR, SUM(AMT) AS TOTAL
FROM SALES
GROUP BY GROUPING SETS((DEPTNO, YR), DEPTNO, ())
ORDER BY DEPTNO, YR;
```

이 쿼리는 `ROLLUP(DEPTNO, YR)`과 똑같은 7행(상세 4행, 부서별 소계 2행, 총계 1행)을 돌려줘요.

- 총계가 필요하니 `()`를 꼭 넣어야 해요. GROUPING SETS는 나열하지 않은 그룹은 만들지 않아서, 빼면 총계 650 행이 사라져요.
- ROLLUP(A, B)와 ROLLUP(B, A)가 다르듯이, ROLLUP(YR, DEPTNO)에 해당하는 건 `GROUPING SETS((YR, DEPTNO), YR, ())`예요. 가운데 소계가 B가 아니라 YR이 됩니다.

```sql
WHERE DEPTNO <> 10 AND DEPTNO <> NULL
```

예를 들어 DEPTNO가 20인 행을 계산해 보면:

1. `20 <> 10` → TRUE
2. `20 <> NULL` → UNKNOWN
3. `TRUE AND UNKNOWN` → UNKNOWN

결과가 UNKNOWN이라 행이 버려져요. 목록에 NULL이 하나라도 있으면 **어떤 값이든** 마지막 비교에서 UNKNOWN이 되니까, 끝까지 TRUE가 될 수 없어요. 그래서 0행이 나와요.

반대로 `IN`은 `=`를 OR로 잇는 거라서, 하나라도 TRUE면 전체가 TRUE예요. NULL이 섞여도 일치하는 값은 정상적으로 찾아져요. NOT IN만 문제가 돼요.

## 이 단원의 EMP 데이터로 확인

```sql
-- 0행이 나와요 (서브쿼리 결과에 NULL인 조미정의 DEPTNO가 포함됨)
SELECT ENAME FROM EMP
WHERE DEPTNO NOT IN (SELECT DEPTNO FROM EMP WHERE ENAME = '조미정');
```

서브쿼리 결과가 `(NULL)`뿐이라 모든 행이 UNKNOWN이 돼요.

## 해결 방법

1. 서브쿼리에서 NULL을 걸러요.
   ```sql
   WHERE DEPTNO NOT IN (SELECT DEPTNO FROM EMP WHERE DEPTNO IS NOT NULL)
   ```
2. `NOT EXISTS`를 써요. 이쪽이 NULL에 안전해서 더 권장돼요.
   ```sql
   SELECT E.ENAME FROM EMP E
   WHERE NOT EXISTS (SELECT 1 FROM EMP X WHERE X.DEPTNO = E.DEPTNO AND X.ENAME = '조미정');
   ```

## 정리

| 연산 | 목록에 NULL이 있을 때 |
| -- | -- |
| IN | 일치하는 값은 정상적으로 찾아요 |
| NOT IN | 모든 행이 UNKNOWN이 되어 0행이 나와요 |
| NOT EXISTS | NULL의 영향을 받지 않아요 |

참고로 위 NOT EXISTS 예시는 조미정의 DEPTNO가 NULL이라 `X.DEPTNO = E.DEPTNO`가 항상 UNKNOWN이 되어, 결과적으로 모든 행이 반환돼요. NULL을 의도대로 처리하려면 이 점도 함께 염두에 두세요.

**RANK** is a window function that assigns a ranking to each row based on the `ORDER BY` criteria.

**How it works**
- A row's rank is the number of rows ahead of it plus 1.
- Tied rows get the same rank, and the next rank is skipped. For example, 1, 2, 2, 4.
- Unlike `GROUP BY`, it does not reduce the number of rows. Each row keeps its own result.

**Comparison with similar functions**

| Function | Ties | Rank after a tie |
| -- | -- | -- |
| RANK | Same rank | Skipped (1, 2, 2, 4) |
| DENSE_RANK | Same rank | Not skipped (1, 2, 2, 3) |
| ROW_NUMBER | Different numbers | Just 1, 2, 3, 4 |

**Example**
```sql
SELECT ENAME, SAL,
       RANK() OVER (ORDER BY SAL DESC) AS RK
FROM EMP
WHERE SAL IS NOT NULL;
```
- 김대표 (9000) gets 1.
- 이개발 and 박영업 (both 6000) each get 2, because only one person is ahead of them.
- 최코드 and 정코드 (both 4000) each get 4, because three people are ahead of them. Rank 3 does not exist.

**Things to remember**
- Adding `PARTITION BY DEPTNO` ranks within each department separately.
- In Oracle, NULL is treated as the largest value. With `DESC`, a NULL row such as 서인턴 becomes rank 1. Use `NULLS LAST` to push it to the end.
