GROUP BY에 쓴 컬럼이라면 HAVING에 일반 컬럼 조건도 쓸 수 있어요. 묶은 뒤에는 그룹마다 값이 하나로 정해지는 것만 쓸 수 있다는 SELECT의 규칙이 HAVING에도 똑같이 적용되기 때문이에요. 다만 이 단원은 HAVING의 컬럼 조건을 직접 다루지 않아서, 이 부분은 GROUP BY 규칙에서 이어 설명한 거예요.

```sql
SELECT DEPTNO, COUNT(*)
FROM EMP
GROUP BY DEPTNO
HAVING DEPTNO = 10;   -- 가능: GROUP BY에 쓴 컬럼
```

반대로 `HAVING ENAME = '김대표'`처럼 GROUP BY에 없는 컬럼을 쓰면 10번 부서에 이름이 여러 개라 값이 하나로 정해지지 않아서 오류가 나요.

> [학습자] WHERE랑 HAVING 차이가 뭐예요?
>
> [AI] WHERE는 그룹으로 묶기 전에 행을 거르고, HAVING은 묶은 뒤에 그룹을 걸러요. SQL은 FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY 순서로 처리돼요.

WHERE를 처리하는 시점에는 아직 그룹이 없어서 SUM이나 AVG 같은 집계 값도 없어요. 그래서 집계 함수를 쓰는 조건은 WHERE에 쓸 수 없고 HAVING에 써야 해요. WHERE에 쓰면 ORA-00934 오류가 나요.

```sql
SELECT JOB, AVG(SAL)
FROM EMP
WHERE DEPTNO = 10        -- 묶기 전: 10번 부서 행만 남김
GROUP BY JOB
HAVING AVG(SAL) >= 4000; -- 묶은 뒤: 평균 4000 이상인 그룹만 남김
```
